## From recursion to DP

Many problems have a natural recursive answer: the number of ways to climb n stairs is the ways for n − 1 plus the ways for n − 2. Written as plain recursion, that's correct and exponentially slow, because the same smaller problems are solved again and again. Dynamic programming (DP) fixes exactly that, in one of two ways:

- **Memoisation (top-down):** keep the recursion, and cache each answer the first time it's computed. In Python, `@cache` does it in one line.
- **Tabulation (bottom-up):** fill a table from the smallest problems up, so that every answer you need is already there.

```python run title=Three_ways_to_count_stairs
from functools import cache

calls = 0
def plain(n):  # correct, but solves the same subproblems over and over
    global calls
    calls += 1
    return 1 if n <= 1 else plain(n - 1) + plain(n - 2)

@cache
def memo(n):  # the same recursion, each answer computed once
    return 1 if n <= 1 else memo(n - 1) + memo(n - 2)

def table(n):  # bottom-up: smallest answers first
    ways = [1, 1] + [0] * (n - 1)
    for i in range(2, n + 1):
        ways[i] = ways[i - 1] + ways[i - 2]
    return ways[n]

print("plain:", plain(25), "after", calls, "calls")
print("memo: ", memo(25))
print("table:", table(25))
```

Every DP solution answers four questions. Get them right and the code almost writes itself:

1. **State:** what does one subproblem look like? ("the best total from the first i houses")
2. **Transition:** how does a state's answer follow from smaller states? ("skip house i, or take it and add the best up to i − 2")
3. **Base case:** which answers are known without any work? ("no houses: 0")
4. **Order:** in which order must states be computed so their inputs are ready? ("increasing i")

:::gotcha Recursion depth with `@cache`
A memoised recursion still nests one call per level. Plain Python stops at 1,000 nested calls. On this page the limit is 100,000, and because `@cache` here adds a frame of its own, a cached recursion can go about 50,000 levels deep. For long inputs, such as 100,000 houses, write the bottom-up version: a loop has no depth limit.
:::

## 1D: one index of state

The simplest DP has one number per position. [[p:198]] decides house by house: skip it, or take it and skip its neighbour. Each cell of the table reads two earlier cells:

The same "last step" thinking solves the rest of the 1D problems:

- [[p:70]] and [[p:746]]: the last move came from one step or two steps below.
- [[p:91]]: the last letter used one digit or two.
- [[p:139]]: the last word ends here and starts somewhere earlier.
- [[p:322]]: the last coin was one of the coin values, so try each.
- [[p:213]]: break the circle into two rows and solve each one.
- [[p:152]]: a product can flip sign, so track both the largest and the smallest value ending at each position.

## Choosing the state

The hardest step is usually deciding what a state is. Some patterns:

- **A prefix:** "the answer for the first i elements" (house robber, decode ways, word break).
- **An ending:** "the best subsequence that *ends at* i" ([[p:300]]), or "the best run ending at i" ([[p:53]] in the greedy module). Useful when the answer must be contiguous or ordered.
- **A pair of prefixes** for two strings: "the first i letters of one and the first j of the other" (LCS, edit distance).
- **A range** `[l, r]` when the problem shrinks from both ends or splits in the middle ([[p:312]]).
- **Extra flags** when the past matters in a small way: "holding a share or not", "cooling down" ([[p:309]]).

If the transition needs information the state doesn't have, the state is too small; if there are far more states than the input suggests, it's probably too big.

## 2D grids and strings

Two inputs, or a grid, give a two-dimensional table. In [[p:62]] each cell adds the cell above and the cell to the left. For two strings, cell `(i, j)` answers the question for the first i letters of one and the first j of the other, and the transition looks at the last letters. Edit distance ([[p:72]]) is the classic: keep matching letters for free, otherwise pay 1 for the cheapest of replace, delete or insert:

:::viz edit-distance-table
:::

:::gotcha Off by one in table sizes
String tables need a row and a column for the *empty* prefix, so they're `(n + 1) × (m + 1)`, and letter i − 1 belongs to row i. Mixing up "the i-th letter" and "index i" is the most common DP bug: the table looks almost right and every answer is a little off. Write down what `table[i][j]` means, in words, before filling it.
:::

[[p:97]] asks which string supplies the next letter; [[p:115]] counts ways instead of maximising; [[p:10]] matches a pattern where `x*` either takes nothing or takes one more letter while staying on the same star. [[p:329]] is a grid where the order isn't left-to-right: a cell depends on its larger neighbours, so the cells are processed by decreasing value (or explored with a DFS and a cache).

## Knapsack

The **knapsack** family chooses items to reach or maximise a total. In the **0/1** version each item is used at most once; in the **unbounded** version, any number of times. The 0/1 table has a row per item and a column per capacity, and each cell reads only the row above: leave the item out (the cell straight above), or put it in (the cell above and w columns to the left, plus the item's value):

:::viz knapsack-01
:::

Since each row reads only the row above, a single row is enough, updated in place. Then the direction of the inner loop is the only difference between the two versions:

- 0/1 ([[p:416]], and [[p:494]] once it's rewritten as a subset sum): loop the totals **downwards**, so `table[t − x]` still describes the totals reached *without* item x.
- Unbounded ([[p:322]], [[p:518]]): loop **upwards**, so `table[t − x]` may already include x, letting it be used again.

```python run title=Loop_direction_decides_reuse
def reachable(nums, target, upwards):
    can = [True] + [False] * target
    for x in nums:
        totals = range(x, target + 1) if upwards else range(target, x - 1, -1)
        for t in totals:
            if can[t - x]:
                can[t] = True
    return can[target]

print("0/1, downwards:     ", reachable([2, 3, 7], 6, upwards=False))  # no subset of 2, 3, 7 makes 6
print("unbounded, upwards: ", reachable([2, 3, 7], 6, upwards=True))   # 2 + 2 + 2 or 3 + 3
```

:::gotcha Which way does the inner loop go?
The same two lines of code solve two different problems depending on the loop direction. Downwards: each item at most once. Upwards: as often as you like. When a knapsack answer is too generous, check this first. For counting, the order of the loops matters too: coins outside and totals inside counts *combinations* ([[p:518]]); totals outside and coins inside counts *orderings*.
:::

## LIS and LCS

Two classic sequence problems:

- **Longest increasing subsequence** ([[p:300]]). The O(n²) DP keeps, for each index, the longest increasing subsequence ending there. The O(n log n) method keeps, for each length, the smallest number that can end a subsequence of that length; those endings stay sorted, so binary search finds where each new number goes:

:::viz lis-patience
:::

- **Longest common subsequence** ([[p:1143]]). The table of prefix pairs: when the last letters match, extend the diagonal; otherwise take the better of dropping one letter or the other:

:::viz lcs-table
:::

```python run title=LIS_two_ways
from bisect import bisect_left
import random

def lis_quadratic(nums):
    best = [1] * len(nums)
    for i in range(len(nums)):
        for j in range(i):
            if nums[j] < nums[i]:
                best[i] = max(best[i], best[j] + 1)
    return max(best)

def lis_fast(nums):
    tails = []
    for x in nums:
        k = bisect_left(tails, x)
        tails[k:k + 1] = [x]  # replace tails[k], or append when k == len(tails)
    return len(tails)

random.seed(4)
nums = [random.randint(0, 999) for _ in range(800)]
print(lis_quadratic(nums), lis_fast(nums))
```

## State machines

Some problems have a small set of situations you move between, like "holding a share", "just sold" and "free to buy" in [[p:309]]. Track the best value in each situation at each step; each situation's new value comes from the situations that can lead into it. The rules of the problem become the allowed arrows: here, a sale is followed by a forced day of rest before the next purchase.

```python run title=A_state_machine_day_by_day
prices = [1, 4, 2, 7, 3, 8]
hold, sold, free = float("-inf"), 0, 0
for day, p in enumerate(prices):
    hold, sold, free = max(hold, free - p), hold + p, max(free, sold)
    print(f"day {day} (price {p}): holding {hold:>4}, just sold {sold:>4}, free {free:>4}")
print("best profit:", max(sold, free))
```

`-inf` marks a situation that isn't possible yet: on day 0 nothing can have been sold.

## Interval DP

When the answer for a range `[l, r]` comes from splitting the range at some point k, the table is indexed by ranges and filled from short ranges to long ones: O(n²) ranges, each trying O(n) split points, O(n³) in total. The art is choosing what k means. In [[p:312]], k is the balloon burst *last* in the range, because then the two sides never interact. Choosing k as the *first* balloon to burst doesn't work: its neighbours would join and the sides would depend on each other.

Palindromes are ranges too: `s[l..r]` is a palindrome when its end letters match and `s[l + 1..r − 1]` is one. A table over ranges solves [[p:5]] and [[p:647]] in O(n²), and growing outwards from each centre does the same work with O(1) memory, which is why the reference solutions do that.

## Space optimisation

A table only needs to keep what future cells will read. If row i reads only row i − 1, keep two rows, or even one, updated in an order that doesn't overwrite values still needed. If cell i reads only cells i − 1 and i − 2, keep two variables. [[p:198]] drops from O(n) to O(1) memory, and LCS from O(n·m) to O(m):

```python run title=LCS_in_two_rows
def lcs_table(a, b):
    L = [[0] * (len(b) + 1) for _ in range(len(a) + 1)]
    for i in range(1, len(a) + 1):
        for j in range(1, len(b) + 1):
            if a[i - 1] == b[j - 1]:
                L[i][j] = L[i - 1][j - 1] + 1
            else:
                L[i][j] = max(L[i - 1][j], L[i][j - 1])
    return L[len(a)][len(b)]

def lcs_two_rows(a, b):
    prev = [0] * (len(b) + 1)
    for ch in a:
        cur = [0]
        for j, other in enumerate(b, start=1):
            cur.append(prev[j - 1] + 1 if ch == other else max(prev[j], cur[j - 1]))
        prev = cur  # only the previous row is ever read
    return prev[-1]

print(lcs_table("dynamic", "programming"), lcs_two_rows("dynamic", "programming"))
```

The cost is that the full table is gone, so reconstructing the actual subsequence, not just its length, needs the table, or a cleverer method such as Hirschberg's, which recovers it in linear memory by splitting the problem in half.

## Complexity

| Problem | State | Time | Space (optimised) |
|---|---|---|---|
| Climbing stairs, house robber | position i | `O(n)` | `O(1)` |
| Coin change with k coin values | amount | `O(amount · k)` | `O(amount)` |
| 0/1 knapsack, subset sum | item, total | `O(n · total)` | `O(total)` |
| Longest increasing subsequence | length → smallest ending | `O(n log n)` | `O(n)` |
| LCS, edit distance | prefix pair (i, j) | `O(n · m)` | `O(m)` |
| Regex or wildcard matching | suffix pair (i, j) | `O(n · m)` | `O(m)` |
| Interval DP (burst balloons) | range [l, r] | `O(n³)` | `O(n²)` |
| State machine (stocks) | day, situation | `O(n)` | `O(1)` |

The time of a DP is always the number of states times the work per state.

:::interview
Say the four parts out loud before coding: the state ("best[i] is…"), the transition, the base cases, and the order. Start with the recursive version if it's clearer, add `@cache`, then convert to a loop if the interviewer asks about recursion depth or memory. Give the complexity as states × transitions. If you can reduce memory to a row or two variables, mention it.
:::

:::work
DP shows up wherever optimal choices build on each other: diff tools and version control (the lines two versions of a file share are a longest common subsequence), spell checkers and fuzzy search (edit distance), bioinformatics (sequence alignment is edit distance with scores), text layout (Knuth's line breaking in TeX), and resource planning (knapsack). You'll rarely invent a new DP at work, but recognising that a slow recursive solution has overlapping subproblems, and fixing it with a cache, is an everyday skill.
:::

## Quick check

:::quiz
? What makes a problem a good fit for dynamic programming?
- [ ] It has a sorted input
- [x] It splits into smaller versions of itself, and the same ones come up again and again
- [ ] It can be solved greedily
> Overlapping subproblems are what DP saves work on. Without them, plain recursion is already as good.

? What's the difference between memoisation and tabulation?
- [x] Memoisation caches a top-down recursion; tabulation fills a table bottom-up
- [ ] Memoisation is always faster
- [ ] Tabulation only works for 1D problems
> Both solve each subproblem once. Top-down is often easier to write; bottom-up avoids recursion depth limits.

? In a one-row knapsack table, what does looping the totals upwards allow?
- [ ] Each item at most once
- [x] Each item any number of times
- [ ] Nothing different from looping downwards
> Going up, `table[t − x]` may already include item x, so x can be used again: the unbounded knapsack.

? Why does a table for two strings of lengths n and m have n + 1 rows and m + 1 columns?
- [ ] To leave room for the answer
- [x] Row 0 and column 0 stand for the empty prefixes, which are the base cases
- [ ] Python lists are 1-indexed
> The empty prefix is a real subproblem: turning "" into a word, or matching nothing. It needs its own row and column.

? In Burst Balloons, why choose the balloon burst *last* in each range?
- [ ] It's always the largest balloon
- [x] While it stands, it separates the two sides, so they can be solved independently
- [ ] Because the first balloon can't be chosen
> The last balloon is a fixed wall for everything else in the range, which splits the problem into two independent subranges.
:::
