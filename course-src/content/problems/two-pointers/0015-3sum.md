## Task

You get a list of integers `nums`. Find every triple of values `[a, b, c]` with `a + b + c == 0`, where the three values come from three different positions in the list.

Return each distinct triple once. Two triples are the same if they hold the same values, whichever positions they came from. The triples can be in any order, and so can the values inside each triple.

## Constraints

- `3 <= len(nums) <= 3_000`
- `-100_000 <= nums[i] <= 100_000`

## Hints

1. Sort the list first. Then a triple can be built by fixing its smallest value and finding the other two.
2. With the first value fixed at index `i`, the other two must sum to `-nums[i]` inside `nums[i + 1:]`, which is sorted: that is Two Sum II with two pointers.
3. To avoid listing a triple twice, skip a fixed value equal to the previous one, and after a match move the left pointer past equal values.

## Solution

```python solution time="n²" space="n"
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums = sorted(nums)
        out = []
        for i in range(len(nums) - 2):
            if nums[i] > 0:
                break
            if i > 0 and nums[i] == nums[i - 1]:
                continue
            l, r = i + 1, len(nums) - 1
            while l < r:
                s = nums[i] + nums[l] + nums[r]
                if s < 0:
                    l += 1
                elif s > 0:
                    r -= 1
                else:
                    out.append([nums[i], nums[l], nums[r]])
                    l += 1
                    r -= 1
                    while l < r and nums[l] == nums[l - 1]:
                        l += 1
        return out
```

Sorting lets each triple be found exactly once, as smallest value first. For each fixed `nums[i]`, the pair search over the rest is the converging two-pointer walk from Two Sum II, which takes O(n) time, so the whole loop is O(n²). Skipping a fixed value equal to the previous one, and skipping equal left values after a match, removes duplicate triples without a set. Once the fixed value is positive, every sum is positive, so the loop can stop. The sorted copy takes O(n) memory; sorting in place would avoid it but would change the caller's list.

## Alternatives

### Check every triple

```python alt time="n³" space="1" slow oracle
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        found = set()
        n = len(nums)
        for i in range(n):
            for j in range(i + 1, n):
                for k in range(j + 1, n):
                    if nums[i] + nums[j] + nums[k] == 0:
                        found.add(tuple(sorted((nums[i], nums[j], nums[k]))))
        return [list(t) for t in found]
```

The definition turned into code. Storing each triple as a sorted tuple in a set removes duplicates. With n = 1,000 it checks about 166 million triples. (The space figure leaves out the answer itself.)

### Fix one value, then Two Sum with a set

```python alt time="n²" space="n"
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        found = set()
        for i in range(len(nums)):
            seen = set()
            for j in range(i + 1, len(nums)):
                need = -nums[i] - nums[j]
                if need in seen:
                    found.add(tuple(sorted((nums[i], nums[j], need))))
                seen.add(nums[j])
        return [list(t) for t in found]
```

Also O(n²) and no sorting needed, but it leans on a set of sorted tuples to remove duplicates. The two-pointer version is the one interviewers expect, and its duplicate skipping is a good thing to be able to explain.

Without skipping equal values, the same triple is found once for each choice of positions. With `[0, 0, 0, 0]` it reports `[0, 0, 0]` twice.

### Skips duplicates by looking ahead

```python wrong fails="example" test="Example 2"
class Solution:
    def threeSum(self, nums: List[int]) -> List[List[int]]:
        nums = sorted(nums)
        out = []
        for i in range(len(nums) - 2):
            if nums[i] == nums[i + 1]:  # skips the first copy, which may be needed
                continue
            l, r = i + 1, len(nums) - 1
            while l < r:
                s = nums[i] + nums[l] + nums[r]
                if s < 0:
                    l += 1
                elif s > 0:
                    r -= 1
                else:
                    out.append([nums[i], nums[l], nums[r]])
                    l += 1
                    r -= 1
                    while l < r and nums[l] == nums[l - 1]:
                        l += 1
        return out
```

The skip must compare with the previous value, not the next one. Skipping a value because the next one is equal throws away triples that use both copies, like `[0, 0, 0]` or `[-1, -1, 2]`.

## Notes

The same frame handles the variants: "3Sum closest" keeps the sum nearest to a target instead of equal to zero, and "4Sum" fixes two values and runs the pointer walk on the rest, for O(n³). In an interview, mention the duplicate handling before you code it; it is the part people get wrong.
