## Task

You start with capital `w` and may complete at most `k` projects, one after another. Project i can only be started when your current capital is at least `capital[i]`. Completing it adds `profits[i]` to your capital (the starting requirement isn't spent), and each project can be done only once.

Return the largest capital you can end with.

## Constraints

- `1 <= k <= 100_000`
- `0 <= w <= 10**9`
- `1 <= len(profits) == len(capital) <= 100_000`
- `0 <= profits[i] <= 10**4`
- `0 <= capital[i] <= 10**9`

```python oracle
class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        done = [False] * len(profits)
        for _ in range(k):
            best = -1
            for i in range(len(profits)):
                if not done[i] and capital[i] <= w and (best < 0 or profits[i] > profits[best]):
                    best = i
            if best < 0:
                break
            done[best] = True
            w += profits[best]
        return w
```

## Hints

1. Each round, the best move is the most profitable project you can afford right now. Profits are never negative, so taking it never hurts later rounds: it only raises your capital, which can only unlock more.
2. Affordability only grows. Sort the projects by required capital and walk through that order with a pointer: every project the pointer passes stays affordable for the rest of the process.
3. Push the profits of the newly affordable projects into a max-heap, then pop the best. Stop after k rounds, or as soon as the heap is empty.

## Solution

```python solution time="n log n" space="n"
class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        projects = sorted(zip(capital, profits))  # by required capital
        available = []  # profits of the projects we can afford, as a max-heap (negated)
        i = 0
        for _ in range(k):
            while i < len(projects) and projects[i][0] <= w:
                heappush(available, -projects[i][1])  # newly affordable
                i += 1
            if not available:
                break  # nothing affordable now, and nothing will become affordable
            w -= heappop(available)  # take the most profitable one
        return w
```

The greedy choice is safe: any plan that takes a less profitable affordable project this round can swap it for the best one, ending with at least as much capital at every later step, so it can still do everything it planned. The two sorted views make each round cheap. Projects sorted by requirement enter the heap once, in order, as the capital passes their requirement; the heap ordered by profit hands out the best of them.

Sorting is O(n log n), and every project is pushed and popped at most once: O(n log n) in total. The `break` matters: if nothing is affordable now, capital won't grow, so nothing ever will be.

## Alternatives

### A heap of locked projects instead of a sort

```python alt time="n log n" space="n"
class Solution:
    def findMaximizedCapital(self, k: int, w: int, profits: List[int], capital: List[int]) -> int:
        locked = list(zip(capital, profits))  # a min-heap by requirement
        heapify(locked)
        available = []  # profits we can afford, as a max-heap (negated)
        for _ in range(k):
            while locked and locked[0][0] <= w:
                heappush(available, -heappop(locked)[1])  # unlocked: move it across
            if not available:
                break
            w -= heappop(available)
        return w
```

Two heaps instead of a sort and a pointer: a min-heap of the locked projects by requirement, and a max-heap of the affordable ones by profit. Projects move from the first to the second as capital grows. `heapify` is O(n), but every project still costs O(log n) to move across, so the total is the same O(n log n). It suits a stream of new projects better, since a sorted list would have to be kept sorted.

## Wrong answers

### Takes the cheapest project

```python wrong fails="example" test="Example 1"

            if i < len(projects) and projects[i][0] <= w:
                w += projects[i][1]  # the cheapest affordable project, whatever it pays
                i += 1
        return w
```

The requirement only decides *whether* a project can be done; what matters is what it pays. In Example 1 this takes the free project paying 2, then the one paying 5, and ends with 8: it never reaches the 6 that unlocks the project paying 9.

### Keeps going when nothing is affordable

At most k projects doesn't mean exactly k. In Example 2, after two projects nothing more is affordable, the heap is empty, and `heappop` raises `IndexError`. Stop as soon as there's nothing to take.

### Scans every project in every round

```python wrong fails="perf"

```

Correct: each round finds the best affordable project. But it looks at all n projects to do so, O(k · n) in total. In the test, k and n are both 100,000 and there's always an affordable project, so all 100,000 rounds run: 10 billion checks. Sorting once and keeping the affordable ones in a heap does each round in O(log n).
